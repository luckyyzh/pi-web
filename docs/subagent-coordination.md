# 子代理的依赖调度与慢任务协调

适用于 Pi Web 内置子代理。旧的 `Agent` 调用仍有效，无需迁移配置。

## 推荐工作方式

- 按可单独验收的交付物拆分，不要一次把“整个后端”交给一个代理。
- 在 `prompt` 写清目标、负责的文件范围、验收标准；避免父代理和子代理同时修改同一范围。
- 优先产出公共接口约定，让后续工作只依赖必要的前置任务，而不是等待整批代理结束。
- 独立任务用 `run_in_background: true`。一个任务完成后即可安排下一项就绪工作；相关工作可用 `resume` 复用上下文。
- 阶段汇报是待验证的中间结论，不代表完成。需要移交写入任务时，先停止原代理并核对改动，再重新分工。

## Agent 新增可选参数

| 参数 | 行为 |
| --- | --- |
| `depends_on` | 最多 32 个已存在、属于同一父会话的子代理 session ID。仅当这些执行成功完成后才启动。省略时不等待其他代理。 |
| `soft_budget_seconds` | 实际开始执行后的软预算，默认 300 秒，允许 0–86400 的整数；0 禁用提醒。不是强制超时。 |

例如，先拿到接口调查任务的 session ID，再安排依赖任务：

```json
{
  "subagent_type": "general-purpose",
  "description": "实现查询接口",
  "prompt": "只实现约定的查询接口，负责 lib/search.ts；返回改动和针对性验证结果，不修改前端。",
  "run_in_background": true,
  "depends_on": ["已有接口调查任务的-session-id"],
  "soft_budget_seconds": 300
}
```

等待依赖的任务仍标为 `queued`，并带有 `waitingFor`，但不占并发槽，也不会挡住后面已经就绪的任务。依赖完成通过事件唤醒队列，不在后台反复轮询。

依赖失败、取消或中断时，下游不会盲目运行。主代理应先检查失败结果，再修订任务或重试；系统不会自动重试和重新分配。依赖绑定于指定时刻的执行，之后 `resume` 同一 session 不会把旧依赖悄悄改成新任务。

下游会收到有长度限制的依赖结果摘要。依赖完成不表示修改已经合并；worktree 中的改动仍须明确检查和整合，尤其要注意新 worktree 不包含父工作区的未提交修改。

## 阶段汇报与预算提醒

有工具的子代理会获得只报告状态、不写项目文件的 `report_subagent_progress`：

```json
{
  "summary": "已确认接口输入输出，类型在 lib/search-types.ts；尚未完成整体实现",
  "remaining": "实现查询逻辑及单元测试",
  "blocked": "需要主代理确认空结果的处理约定"
}
```

- 汇报在子会话中持久化，父代理可以提前审查、继续不相关工作或调整范围。
- `summary` 最多 2000 字符，`remaining` 最多 2000，`blocked` 最多 1000。
- 后台任务的阶段消息会通知父代理；连续汇报的通知最多每 30 秒一次，最新快照仍会保存。工具调用流水和思考内容不会自动当作阶段成果。
- 软预算从真正执行开始计时，排队时间不计入。达到预算时只提醒一次，并向子代理请求阶段汇报，不自动停止、复制任务或转移文件归属。
- Chat-only 子代理保持无工具；其预算提醒不会给它增加写入或汇报工具。

## 主代理可用工具

- `list_subagents`：查看当前父会话在本服务进程中跟踪的活跃子任务、依赖等待、阶段汇报和软预算提醒。不是持续轮询工具。
- `get_subagent_result`：保留原接口，`queued` 不再误报失败；`wait: true` 默认最多等待 30 秒，可用 `timeout_seconds` 调整为 0–300 秒。等待到限返回当前快照，不代表任务已完成，也不取消任务。独立工作存在时不要阻塞等待。
- `steer_subagent`：调整仍在运行的任务范围；主代理应基于汇报决定继续、缩小目标或拆分剩余工作。

任务卡片显示依赖等待、阶段汇报和软预算提示。软预算与原有 `max_turns` 不同：`max_turns` 仍是轮次限制；强制达到轮次上限而中止的任务不会作为成功依赖放行。

## 边界

这是轻量协调机制，不是自动理解任务复杂度的调度器，也不承诺精确负载均衡。任务拆分和剩余工作分配仍由主代理完成。

- 没有语义级任务去重、文件锁或 shell 写入沙箱；声明文件范围仍需代理遵守。
- 阶段汇报不会自动满足 `depends_on`。需要提前推进时，应把可交付的前置阶段拆成独立任务，或由主代理审查后另行安排独立工作。
- 依赖成功只指子代理执行正常结束，并非主代理已验收业务正确性。
- 服务重启后不自动重放修改任务；没有活跃执行句柄的旧 queued/running 任务查询为 interrupted，需先核对现有改动再显式恢复，不能据此直接判定任务未做过。已被清理的 worktree 会拒绝 resume，应新建隔离任务。
- 直接以前台模式调用 `Agent` 仍会等待该任务结束，保留旧语义。可能较长或有依赖等待的工作应使用后台模式；软预算不会强制结束挂起的模型请求，主代理需按提醒人工判断是否停止。
- 并发限制仍按父会话计算，不是跨父会话的文件冲突防护。
- worktree 为可选的目录隔离，不是权限沙箱；远程工作区目前仍不支持此隔离模式。
